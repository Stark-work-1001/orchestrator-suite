# orchestrator-suite 2.3.0 增量与修复记录

日期：2026-10-12（Asia/Shanghai）。范围仅为本套件源码、产物、自有预设、内部开发依赖、该套件链接与本地交付包。用户要求保留原功能，本次不修改 DSH 本体或其他已安装插件。

## 保留与增量

保留 `dispatch-orchestrator` 模式、现有七个工具、普通模式入口、四层参考的旧提交格式、原始用户消息捕获、系统 section 明文提交记录、非阻塞降级、方案与交付分离、七阶段进度、插件内部技能/MCP/VENV 嵌套与轮询。

五层参考顺序为工具 → 记忆 → 身份 → 组织协作 → 对照验证；工作台中“对照验证层”位于组织协作和调度对照编排之间。验证页明列当前引导工具：`dispatch_review → verifier_compare`（方案），`dispatch_accept → verifier_current_session`（交付）。当前工具表可见性与真实调用结果分开，发现清单不触发裁判调用。

记忆页分类为记忆系统、记忆数据库查询接口、记忆文件、公开查询工具、模型查询记录。relic 引导主模型使用当前可用 MCP/宿主公开 status 接口识别真实协议与端口，再召回任务相关的对话记忆；stdio 明确无 TCP 端口，未知保持未知。不会扫描端口、读取其他插件私有配置、打开数据库或导出、写入记忆库。数据库类别表示公开查询入口，不假装已确认底层存储类型。

身份页显示公共注册表中匹配身份/角色能力的插件和工具，例如实际注册的 `dsh-cosplay`；组织页显示宿主团队、子智能体和 swarm 能力，例如 `dsh-agent-swarm`。名称匹配只是候选识别，不等于已采用角色或已组建团队。套件没有导入这些插件、连接其私有服务或修改它们的配置。

L0/L1/L2 保留，组织页增量显示当前会话实际提交的分诊结论，并允许直接描述目标、子任务、依赖、沟通与验收。引导规定主模型负责整合、子模型在任务书边界内自主执行；依据真实回报动态澄清/调整/取消任务，协调重叠写入，最终复审。不会依据任务级别强制创建子智能体。

新工具 `relic_record_observation` 仅接收当前任务清单中的记忆/身份/组织资源 ID 和明确来源，记录主模型的公开只读查询报告。协议/端点为模型报告，明确标记 `model-reported`，不是独立探测。stdio 不能附 TCP 端点；HTTP(S) 端点拒绝凭据、query、fragment 和协议不一致。报告进入后续系统 section、所选会话看板及任务状态详情；跨任务追加约束时清空旧报告，不混入宿主全局层。

## 界面与修复

- 沿用已有宿主主题 tokens，项目无 DESIGN.md；新增五层统计、分类筛选、工具名、协议/端口、来源与公开可见性展示。
- 任务标题栏保留紧凑形式，增加阶段位置、持续可见的降级数量；详情增加当前阶段、提交证据计数、查询报告与更新时间。阶段位置不是完成百分比，“已有证据”不是裁判通过。
- 保留关闭按钮、Escape、外部点击、窄窗口样式与减少动画偏好。客户端 CSS 由生命周期 effect 管理，卸载清理并可再次启用。
- 修复发现过程中对宿主返回的插件数组原位追加；改为自有副本，兼容冻结注册表数组。
- 避免访问未注入的可选 workingDirectory 服务，使用公开会话 cwd。
- 去重同一套件从资产根与 profile 链接重复发现的真实根目录；技能路径按规范化来源去重；技能目录中的嵌套环境继续扫描。
- 元数据缺失、拒绝读取与解析失败不再全部吞掉；保留正常“无 manifest”跳过，其他情况列出证据缺口。
- 看板及任务状态请求增加超时，避免一次未返回请求永久阻断后续刷新；仍串行轮询、隐藏暂停、不增加无限后台扫描。
- 移除开发脚本对其他插件工具链的运行时回退。内部包以普通文件拷贝保存在本套件 node_modules；开发与测试不依赖原来源插件目录。
- 修复打包入口检查：实际导入解压后的新版本宿主入口；压缩包逐文件 SHA256 核对，包含内部开发依赖及其原 LICENSE 文件。

## 自包含与安装形式

宿主产物只导入 Node 内置模块，服务通过 DSH 公共 `ctx` 和注册表取得。客户端 React 通过宿主公开 ModuleLoader 提供，避免第二份 React 导致 Hook 运行时冲突；内部另包含开发/测试用 React。73 个已有本机开发依赖包被物化进套件 node_modules，没有网络下载；逐依赖解析证实未指向其他插件。依赖版本、落点和检查见 `local-dependencies.json` 与 `dependency-check.json`。

交付目录保持原位（本机绝对路径不随包分发）；自有入口 `lib/host-2.3.0.js`。desktop profile 已有该套件 `link:` 依赖及 bundle 选择，安装脚本只调整该套件的链接类型为 SymbolicLink，不改清单、锁文件、其他 Loader 行或 bundles 数量。旧入口文件暂留本机以兼容当前进程缓存，新包只含当前运行产物。

安装实际完成后，原生 Get-Item 已确认 `LinkType: SymbolicLink`、Target 为该套件目录。profile 四份受保护文件及原有 4064 个其他插件源码/产物文件均与基线一致。核对期间 dsh-memory-connector 的 docs 新增 EMBEDDING-COMPARISON.md、EMBEDDING-SELECTION.md、MODELS.md，原有文件无修改或删除；本任务执行的写入步骤没有涉及这些路径。保留原始基线和新增文件清单，不覆盖这些并发外部新增文档。因此 installation.json 的全量 otherPluginsUnchanged 为 false，但现有受保护文件无漂移；两者不能混写。

## 验证与已知环境问题

验证证据以 `verification.json`、`preflight.json`、`preflight-baseline.json`、`dependency-check.json`、`installation.json` 与 `package.json`（此处为 docs 内打包报告）为准。最终核对包括类型检查、生产构建、旧功能与新增层级回归、客户端导航/分类/关闭/卸载清理、自包含依赖解析、完整 profile 配置组合、安装前后哈希及压缩包解压检查。

当前官方配置检查提示 `dsh-memory-connector` 的补丁不是顶层 YAML 数组，故被宿主跳过。使用 2.2 冻结版组成同一 profile 的独立对照环境，也得到相同提示，确认是已有第三方装配问题；本次未修复该插件，不能声称它在当前宿主可用。记忆层保留该候选并引导根据实际可见工具判断，不能用目录存在或 README 代替连接成功。

此 Codex 会话仍无 SynaBun recall/remember、规定浏览器及 DSH plugin_manager/cordis_inspect_query 工具。无法执行 SynaBun 的跨会话记录或真实 GUI/活体注册表验收；不使用其他浏览器替代。本次不重启桌面应用、不发送付费裁判请求。配置组合和组件测试不代表当前运行进程已加载新模块；实际运行生效与明暗主题验收待有合法入口后核验。

沙箱对 realpath 和链接操作的 EPERM 通过明确的沙箱外命令审批解决，没有绕过宿主安全机制。交付路径和 DSH 链接位于本轮可写工作区之外，仅执行获授权的本套件安装与本地包写入。

## 复现与回滚

解压发布包后，node_modules 及构建工具已在包内；不需借用其他插件。于套件目录执行：

```powershell
node scripts/typecheck.mjs
node scripts/build.mjs
node --test tests/*.test.mjs
node scripts/check-dependencies.mjs
node scripts/preflight.mjs
```

通过 DSH 官方插件管理应用/安全重启后，新建普通模式和调度对照编排模式会话，核验原流程仍可运行。打开工作台确认七项导航、新验证层位置、实际工具名称、记忆分类、身份/团队资源；选定会话后查询公开 status/recall，调用 relic_record_observation，确认记录为模型报告且来源可见。没有协议/端口证据时应显示未知；stdio 无端口。验证失败可降级继续，不伪造验收。

标题栏核验阶段位置、降级提示、查询报告、三种关闭方式、窄窗口、明暗主题及隐藏暂停。中途追加约束应清空旧评价/报告。

2.2 源码及运行时冻结在 `archive/2.2.0`。回滚用该目录中的 package.json、cordis.patch.yml、suite.config.json、src、lib、presets、locale、scripts、tests 恢复对应文件，保留或移开新增内部 node_modules 均不影响旧运行产物；必要时恢复安装脚本记录的旧链接。之后通过官方入口应用并核验旧工具与模式。不得恢复其他插件或用旧哈希覆盖本机后续变化。
