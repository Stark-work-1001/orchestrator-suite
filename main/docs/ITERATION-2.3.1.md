## 合并阶段状态与内容

任务进度面板只有七个阶段行，顺序仍为用户提示词、任务分诊、多层对照、第三方验证、综合装配、执行任务、交付验收。每行是可用键盘操作的原生 details/summary：收起时显示展开箭头、状态灯、名称、状态文字；展开后显示同一阶段的对应内容。

| 阶段 | 展开内容 |
| --- | --- |
| 用户提示词 | 保持换行与原文的用户原始输入 |
| 任务分诊 | 主模型实际提交的分诊 |
| 多层对照 | 实际多层判断及可展开的公开查询记录 |
| 第三方验证 | 真实裁判结果，或本阶段未取得结果和降级原因 |
| 综合装配 | 主模型实际综合执行结论 |
| 执行任务 | 宿主观察到的执行状态与开始/结束时间；不伪造执行总结 |
| 交付验收 | 真实交付评价与结果边界，或未取得结果及原因 |

状态文字与灯一直位于 summary，不因详情收起而隐藏。用户展开状态在同一任务的自动刷新中保留，切换会话/新任务重新收起；长输入与结果在本阶段内滚动，不再重复成下半部分列表。保留顶部当前状态和降级提醒；验证边界说明放入独立的折叠说明，降低固定区域占用。

新增可选的 `ProgressStep.note` 保存本阶段提示/错误。资产发现、方案验证、交付验证和宿主错误分别写入对应阶段，避免把最后一个全局错误混贴到多个阶段；旧接口的 progress.error 仍保留兼容。成功重试或显式重置会清理旧原因。降级允许独立工作继续，取消/暂停和本轮结束仍不等于验收通过。

## 复现与回滚

在套件目录执行 `node scripts/verify.mjs` 可复现本地检查。应用版本后，发送任务并打开标题栏进度：确认只有七行，每行收起时有灯和状态文字；逐行展开检查对应内容，特别是降级验证的原因、执行时间和验收边界。等待刷新确认展开仍保留，追加约束或切换会话应重置。看板切换范围、独立资产分类、任务记录和宽/窄窗口应一致；明暗主题与运行中工具可见性仍需真实宿主核验。
