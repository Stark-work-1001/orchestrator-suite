# Orchestrator Suite 3.0 架构迭代

本次将架构从平铺执行链改为引导式“规划 → 执行反应 → 验收交付”。所有步骤展示已提交的公开理解；建议可以调整、跳过或不采纳，不把裁判或提交工具作为工作门禁。

- 规划：按可配置首条提示词阈值建议完整规划；汇总原始输入、分诊、当前 DSH 的工具/验证/团队协作/身份四层与现有第三方结果，形成综合装配规划。
- 执行反应：原始提示词不变；每次补充独立记录、理解和影响评估，增量修改计划版本与带来源的待办；重复保留原文而不重复修改。
- 验收交付：连接初始与全部过程需求、计划及待办变化与实际成果，输出完整原文和报告，独立列出建设需求。第三方评分仍不自动等于通过。
- 身份：按阶段和任务规模报告静态/动态、依据与变化/保持理由，职责变化不自动修改其他角色插件。
- 界面：看板与标题栏统一三阶段、11 步骤；理解、身份、增量、历史与导出可展开查看。
- 部署：仅原位更新本套件发布文件，保留本地配置、旧入口和外部 profile；覆盖前备份，外围文件哈希核验。

第三方接口沿用 `verifier_compare` 与 `verifier_current_session`；不改裁判内部实现、模型配置与门槛。记忆保留为可选资料，不纳入四层架构验证。

实际检查结果由 RELEASE-SUMMARY.json 和本机 verification/preflight/installation 报告分别提供。进程内任务记录不跨重启自动恢复，需导出报告。历史 ITERATION-2.* 文件仅为历史记录。
